T14: M5 Distributed Write Path / 2PC¶

状态：已完成（代码 + 测试 + 文档 + README 全量落地） 对应：开发手册 §10（分布式写事务）；README Roadmap「M5 distributed write path: cross-node transactions / 2PC」 提交：见 git log（T14_m5_2pc）

背景¶

M4 已实现多节点拓扑（NodeInfo 注册表、心跳、路由表 region→node）与跨节点读路径 （SELECT 转发 + 合并），但跨节点写路径仍被拦截 （write to remote region ... not supported）。M5 在 M4 帧格式与路由之上实现 跨节点两阶段提交（2PC）：一条写语句（INSERT / UPDATE / DELETE / CSV IMPORT） 同时命中本地与远端 region 时，协调者（发起节点）保证跨节点原子提交/回滚， 并保持单节点部署零触发、零回归。

架构总览¶

                    ┌───────────────────────────────┐
                    │ 协调者 (Coordinator = 发起节点)   │
                    │  pkg/sql/2pc.go  Executor       │
                    │  autocommit 写语句               │
                    └───────────────┬───────────────┘
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │ 本地 region                │ 远端 region                 │
        │ applyOps → 本地事务缓冲      │ cluster.Manager            │
        │（M1-M4 txn.WAL 语义）      │ PREPARE/COMMIT/ABORT 帧     │
        ▼                           ▼                           ▼
 ┌──────────────┐          ┌───────────────────────────────────────┐
 │ 本地存储       │          │ 参与者 (Participant = 远端节点)          │
 │ WAL + RocksDB │          │ pkg/cluster/txn2pc.go Server          │
 └──────────────┘          │ prepare 落盘 m:2pc:p / commit 落盘     │
                           │ m:2pc:c / abort 落盘 m:2pc:a，幂等     │
                           └───────────────────────────────────────┘

写语句先在 SQL 层产出物理键操作列表（行键 / 二级索引键的 Put / Delete， pkg/sql/2pc.go: kvOp），按 region 归属分组（groupOps）：

  • 本地 region → 协调者本地事务缓冲（原 M1-M4 applyOps 路径）；
  • 远端 region → 按归属节点聚合成组，经 cluster.Manager 走 2PC 协议帧。

2PC 状态机¶

协调者视角（pkg/sql/2pc.go: exec2pcWrite）：

                    ┌──────────────┐
        ┌──────────▶│   Prepared   │◀──────────┐
        │           └──────┬───────┘           │ 任一 PREPARE 失败
        │        全部就绪   │                   │
        │                  ▼                   ▼
        │           ┌──────────────┐     ┌──────────────┐
        │           │  LocalCommit │     │   Aborting   │──▶  Aborted
        │           └──────┬───────┘     └──────────────┘
        │           本地提交成功│
        │                  ▼
        │           ┌──────────────┐
        └───────────│ RemoteCommit  │──▶  Committed（全部幂等 COMMIT）
                    └──────────────┘

参与者视角（pkg/cluster/txn2pc.go）：

  PREPARE ──▶ prepared（ops 落盘 m:2pc:p:<txid> + 内存缓存）
                │
        ┌───────┴────────┐
        ▼                ▼
    COMMIT ──▶ 原子应用（WriteBatch：数据 + 删 p 标记 + 写 c 标记）──▶ committed
    ABORT  ──▶ 丢弃（删 p 标记 + 写 a 标记）──────────────────────▶ aborted
  • commit2pc / abort2pc 幂等：已提交直接 OK；未 prepare 但落盘记录存在时 读盘恢复 ops 后重放（协调者重试 COMMIT / 迟到 ABORT 安全）；
  • 已 aborted 后迟到 PREPARE / COMMIT 被拒绝（返回明确错误）。

协议帧（M4 帧格式扩展）¶

Type 名称 方向 载荷
22 msg2pcPrepareReq 协调者 → 参与者 PrepareReq{TxID, Ops[]}（JSON）
23 msg2pcPrepareResp 参与者 → 协调者 PrepareResp{Err}
24 msg2pcCommitReq 协调者 → 参与者 CommitReq{TxID}
25 msg2pcCommitResp 参与者 → 协调者 CommitResp{Err}
26 msg2pcAbortReq 协调者 → 参与者 AbortReq{TxID}
27 msg2pcAbortResp 参与者 → 协调者 AbortResp{Err}

TxnOp{Key, Value, Delete} 为跨节点物理写单元（与 SQL kvOp 一一对应， 按 region 前缀直接落到归属节点存储，无需重新路由）。TxID 由协调者生成 （2pc-<unixnano>-<seq>），参与者以其为幂等键。

执行路径¶

prepare（参与者）¶

  1. 校验 txID 非空、未被 abort；已 committed / 已 prepared 幂等 OK；
  2. ops 序列化落盘 m:2pc:p:<txid>（崩溃可恢复），内存缓存 pending2pc[txID]；
  3. 返回 OK。任何失败返回错误，协调者进入 abort。

commit（参与者）¶

  1. 已 committed 直接 OK（幂等重放）；
  2. 已 aborted 拒绝（协调者不应在 abort 决策后重试 COMMIT）；
  3. 取内存 pending2pc[txID]（丢失则从 m:2pc:p:<txid> 读盘恢复）；
  4. 单 WriteBatch 原子应用：数据变更 + 删除 prepared 标记 + 写 committed 标记。

abort（参与者）¶

  1. 已 aborted 直接 OK（幂等）；
  2. 已 committed 拒绝（协调者决策与参与者状态冲突，报错暴露不一致）；
  3. 删除 prepared 标记 + 写 aborted 标记（不触碰任何数据）。

协调者（exec2pcWrite）¶

1. applyOps(本地组)          → 本地事务缓冲（未提交）
2. 全部参与者 PREPARE        → 任一失败：abort 已就绪者 + 返回 TXN_PREPARE_FAILED
3. tx.Commit()（本地）        → 失败：abort 已就绪者 + 返回 TXN_COMMIT_ABORTED
4. 全部参与者 COMMIT（幂等重试）→ 失败：返回 TXN_COMMIT_UNCERTAIN
   （本地已提交，参与者可重试幂等 COMMIT，不丢数据）

与既有链路的关系¶

链路 关系
本地 WAL / M1-M4 txn 本地组仍走原 txn.Txn.Put/Delete + Commit（WAL + RocksDB WriteBatch 原子性），2PC 不改变本地事务语义
M2 binlog 参与者 COMMIT 复用存储引擎单次 WriteBatch，binlog hook（若开启）随本地提交自然触发，与 2PC 标记同批落盘
M3 region 归属 写操作按 sharding.DecodeRegionKey 判定归属；region 边界/前缀编码不变
M4 路由 远端节点地址取自 cluster.Manager 注册表（region→node 路由视图），ADD NODE 幂等重注册支持节点重启换地址后重新加入

失败与恢复语义¶

  • 参与者崩溃于 prepare 后、commit 前：重启时 Recover2PC() 扫描 m:2pc:*， 清理全部标记（prepared 未决事务回滚——协调者侧超时/重试后按 aborted 处理）；
  • 协调者超时 / 网络中断：TXN_COMMIT_UNCERTAIN，本地已提交、 参与者可重试幂等 COMMIT 收敛；
  • 参与者 prepare 失败：协调者 abort 已就绪参与者，本地组回滚 （本地行不残留）；
  • 重复 COMMIT / ABORT：参与者幂等标记（m:2pc:c / m:2pc:a）保证安全。

单节点兼容¶

Executor.mgr == nil（未启用集群）或全部 region 本地时：

  • exec2pcWrite 走 applyOps + tx.Commit()，与 M1-M4 完全一致；
  • 无任何 m:2pc:* 标记落盘（零触发），测试 TestM5SingleNodeZeroRegression 验证。

显式事务限制¶

M5 2PC 支持 autocommit 语句与 CSV IMPORT 批量路径；BEGIN..COMMIT 显式事务 内的跨节点写返回明确错误 （distributed write inside explicit transaction not supported in M5 (autocommit 2PC only)）， 本地显式事务行为不变。会话级分布式事务（TSO + 跨节点事务上下文）为后续集群演进方向。

错误语义¶

错误 含义
TXN_PREPARE_FAILED: 2pc <id> participant <node>: ... prepare 阶段失败，整笔回滚
TXN_COMMIT_ABORTED: local commit failed for 2pc <id>: ... 协调者本地提交失败，已 abort 参与者
TXN_COMMIT_UNCERTAIN: 2pc <id> participant <node>: ... 远端 COMMIT 失败，本地已提交，可重试幂等 COMMIT

设计取舍¶

  • 协调者不落盘决策：M5 选择“参与者 prepare 落盘 + 幂等标记”保证崩溃可恢复； 协调者本地事务即决策点（协调者崩溃=本地事务未提交/已提交，语义自洽）， 避免引入额外决策日志，换取最小侵入。
  • 参与者崩溃恢复策略：Recover2PC 全清（prepared 一律回滚）——单语句 autocommit 场景协调者重试/后续语句幂等收敛，简化恢复逻辑。
  • 帧格式沿用 M4 JSON 载荷：与 NODE_HELLO / REGION_PUSH 一致，便于调试与 测试注入（SetPrepareFail 故障钩子仅测试路径）。
  • 显式事务不支持跨节点写：明确报错而非静默降级，为后续会话级分布式事务 保留接口语义。

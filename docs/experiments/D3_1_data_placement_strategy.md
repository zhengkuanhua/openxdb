## 2. 候选策略定义

### 2.1 显式 REGION 指派（SPLIT/ASSIGN，隐式显式化）

数据以 **region（主键区间）** 为分布与路由的基本单元：

- **切分**：`SPLIT REGION` / `SplitTable` 按主键字节边界把表切分为连续无重叠的显式 region（M3，T12 §2.4）；
- **指派**：`ASSIGN REGION <id> TO NODE '<nodeID>'` 三步走——源节点扫描 region 全量物理数据 → `REGION_PUSH` 推送到目标节点（数据 + 权威路由视图原子落盘）→ 源节点更新路由归属并落盘 `m:regions`（M4，T13 §数据装载）；未 SPLIT 的表（隐式单 region `tableID|1<<63`）**先显式化注册再指派**；
- **路由**：`SHOW REGION ROUTES` 一表查看 region/table/start/end/node/local；`Node=="" || Node==selfID` 的 region 本地执行；
- **读**：`getKVCluster` / `scanMergedCluster` 按 region 归属选择本地直读或远端 QUERY_REQ 转发 + 合并（M4，T13 §跨节点查询执行路径）；快照隔离经 TSO 全局时间戳透传 `begin_ts`（M8，T17 §2.3）；
- **写**：跨 region 写走 2PC 协调者/参与者状态机（M5，T14），跨节点原子提交/回滚；
- **运维**：节点 down 后 region 自动重指派 + 读 failover（M6，T15 §2.2/2.3）；`BALANCE` 在线迁移、写路径自动分裂（M7，T16）。

### 2.2 广播表（Broadcast Table）

数据以**整表副本**为单元：每个节点持有表的全量副本，读可在任意节点本地执行，写需同步到所有副本节点。

OpenXDB 现状中的近似机制是 M2 binlog 复制（T11）：主从异步复制、`follower` 读可能滞后、**不承诺强一致读**（T11 §5）；T33 sync/semi-sync 热切换已存在但面向复制模式而非广播表语义。**当前仓库没有"同步广播写"通道**：广播表若落地，需要新增：

1. 写广播协议：写语句同步下发全部节点并确认（等价于对每个写执行"全参与 2PC"，写放大 O(N)）；
2. 冲突消解：多主写同一行的冲突检测（现约定从端仅通过复制写入，无多主写机制）；
3. 一致性保证：同步复制下的读一致，或显式接受滞后读。

在 OpenXDB 的物理键体系（全部键带 region 前缀，M3）下，广播表仍绕不开 region 概念——它等价于"**把表的全部 region 都指派到每个节点 + 同步复制**"，即显式指派的一种退化形态（每节点持全量 region），而非平行路线。

## 3. 对比分析

| 维度 | 显式 REGION 指派 | 广播表 |
| --- | --- | --- |
| 数据放置单元 | region（主键区间），各节点持有部分 | 整表副本，每节点持有全量 |
| 容量扩展 | 随节点数线性扩展（数据分散，存储≈数据量/N） | 不扩展（每节点全量，存储≈数据量×N） |
| 写路径 | 按 region 归属写目标节点；跨 region 2PC（M5 已实现） | 需同步广播全部节点，写放大 O(N)；或降级异步复制（滞后） |
| 读路径 | 本地直读 + 远端转发合并（M4 已实现） | 任意节点本地读（无转发） |
| 跨节点一致性 | TSO + 分布式快照隔离（M8 已实现，跨节点透传 begin_ts） | 依赖新增同步广播协议；异步复制不承诺强一致读 |
| 热点处理 | 自动分裂 + BALANCE 在线迁移（M7 已实现） | 无读热点问题，但写热点被 N 倍放大 |
| 故障恢复 | region 自动重指派 + 读 failover（M6 已实现） | 需副本间同步/追赶机制（M2 异步复制近似） |
| 可用性耦合 | 写仅依赖归属节点 + 2PC 参与者（部分节点） | 写依赖全部节点：任一节点故障阻塞全局写或牺牲一致性 |
| 运维可观测 | `SHOW REGION ROUTES` 路由表可见、可解释 | 无路由表概念，需复制状态视图 |
| 与既有机制契合度 | 高：M3-M8 全部以 region 为公共单元 | 低：需新建广播写通道；与分片/迁移/分裂机制重叠 |
| 适用数据 | 大表、容量/负载敏感、主键可切分 | 小维度表、读多写少、要求任一点本地读 |

## 4. 推荐结论：显式 REGION 指派优先

**结论：v1.18.0 D3 数据分布采用显式 REGION 指派（SPLIT/ASSIGN，隐式显式化）优先；广播表不进入本版本实施，列为后续版本增强。**

### 4.1 依据

1. **机制就绪度（决定性）**：M4 跨节点读 + 隐式显式化（T13）、M5 2PC（T14）、M8 TSO + 分布式快照（T17）、M6 failover（T15）、M7 分裂/均衡（T16）均已实现并通过全仓回归。显式指派"选型即落地"：D3.2 只需执行建表 → `ASSIGN REGION` 管理操作，**零新协议**。广播表则需要从零新增同步广播写协议与冲突消解，周期不可控。
2. **与既有机制同构**：region 是 M3 分片（T12）、M4 路由（T13）、M5 2PC（T14）、M6 failover（T15）、M7 迁移/分裂（T16）的**公共操作单元**；广播表与这套机制重叠（仍需 region 概念才能复用读路径），其本质是"全 region 全节点副本"的退化形态，应作为显式指派之上的**增强特性**（后续版本）而非平行路线。
3. **容量与负载目标**：D3 的目标是"跨节点数据分布"——分担容量与负载。显式指派数据分散、容量随节点线性扩展；广播表三节点 = 3 倍存储 + 3 倍写放大，与目标背道而驰。
4. **写放大与可用性**：显式指派写只触及归属节点 + 2PC 参与者（部分节点故障不影响无关 region 写）；广播表同步写全节点，任一节点故障阻塞全局写（或降级牺牲一致性），可用性耦合风险高。
5. **HA 灰度衔接（D4）**：D4.2 宕机 failover 演练要求 region 粒度自动重指派（`resolveRegionOwner`，M6），显式指派直接复用；广播表场景的 failover 变成"副本追赶/同步"，与 D4 目标（region 重指派 + epoch + 回迁）不对齐。
6. **可观测与可回退**：`SHOW REGION ROUTES` 提供路由可观测；ASSIGN 是管理操作、数据保留在源节点（T13 一致性约定），失败可回退隐式单 region（详见 §5）。
7. **业界佐证**：TiKV 以 region（Raft group）为分布单元叠加 RocksDB 事务层，与 OpenXDB M3-M8 路线同构（storage_engine_selection.md §3/§4 已引用该佐证）；以"主键区间分片 + 路由"作为分布式数据库主路径是成熟路线。

### 4.2 适用场景

**显式 REGION 指派（本版本优先）**：

| 场景 | 说明 |
| --- | --- |
| 大表容量扩展 | 数据量超过单节点容量，需按主键分散到多节点 |
| 跨节点聚合读 | COUNT/SUM 跨 region 聚合不丢不重（D3.3 专项验证） |
| 访问局部性明确 | 数据可按主键切分，热点集中在特定 region |
| 写吞吐敏感 | 写放大为常数（1 份 + 2PC 参与者），不受节点数线性放大 |
| 需要迁移/均衡/failover | region 粒度在线迁移（M7）、自动重指派（M6） |
| HA 灰度验证场 | 三节点真实组网，region → node 路由可见、可演练 failover |

**广播表（后续版本增强，本版本不实施）**：

| 场景 | 说明 |
| --- | --- |
| 小维度表 | 配置表、字典表、公共码表：数据量小、每节点都需要完整副本 |
| 读多写少 | 读可在任意节点本地执行，写极少（广播写放大可接受） |
| 三节点以下、副本可控 | 副本数 = 节点数，N 小时写放大可控 |
| 与显式指派混用 | 分区大表 + 广播维度表（星型模型维度广播），作为增强而非替代 |

## 7. 结论

- **推荐显式 REGION 指派（SPLIT/ASSIGN，隐式显式化）优先**：机制已就绪（M4/M5/M8/M6/M7 全链路）、与既有 region 体系同构、容量线性扩展、写放大常数、HA 灰度可直接复用 region 粒度 failover；
